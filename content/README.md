# content/ — the hand-written batches

Scripts are written by hand in a monthly Claude Code session (flat-rate
subscription) instead of by the metered API. This folder holds the source of
each batch, so a batch can be re-checked, corrected and re-ingested without
anybody retyping it.

One file per batch, named for the month it was written: `batch_2026_09.py`.

## What a batch file contains

For each video, one `add(...)` block holding:

- the **concept** — title, anchor number, mechanism, cluster, hook pattern, sources
- the **five beats** — hook, turn, mechanism, spike, loop (see `style.md`)
- the **visual plan** — two to four visuals per beat, each with a real
  direction, not a placeholder

`overlay` is not decoration: the opening frame is extracted after rendering and
uploaded as the video's YouTube thumbnail, so that line of text and the first
beat's visual are what a stranger sees before they have watched anything. Write
them as a pair.

The shot list is *built*, never typed. `build_shots()` splits each beat's exact
words across that beat's planned visuals, so the shot narration always
reconstructs the script word-for-word. That removes the one failure mode that
silently desyncs a whole video.

Because of that split, a beat's length and its number of planned visuals
together set how long each image stays on screen. The builder rejects any shot
over `MAX_SHOT_SECONDS` (5s): a long beat with two visuals is a slideshow, and
the fix is more visuals, not a shorter beat.

## Running one

```
python content/batch_2026_09.py             # validate only, writes nothing to data/
python content/batch_2026_09.py --ingest    # validate, then load into the bank + queue
```

Validation is the project's own `gen_scripts.validate_script()` — the same gate
the API path has to pass. Nothing skips a check just because a human wrote it.
The dry form prints, per script, the format letter, spoken runtime, shot count
and word count, plus any accuracy-trap warnings for a human to answer.

`--ingest` writes concepts to `data/idea_bank.jsonl` first (the bank assigns the
real `cb-NNNN` ids), then queues the scripts against those ids in the same
process. Doing both in one run is deliberate: pairing scripts to concepts by
hand is the one step where a mistake would be invisible.

**Re-running `--ingest` is safe.** Concepts already in the bank are matched by
title rather than added again, and any of their entries still sitting in the
queue are rewritten with the corrected script and shot list. Entries that have
already been popped or published are left exactly as they shipped. So the loop
is: fix the batch file, re-run with `--ingest`, commit.

## Format rotation carries across batches

`gen_scripts.last_format_used()` reads the tail of the queue, so a new batch
continues the A–E rotation rather than restarting it. Two same-shaped scripts
back to back is rejected, not warned about — `style.md` §3 treats it as a
monetization risk rather than a matter of taste.

## After ingesting

The queue (`data/script_queue.json`) and the bank must both be committed. The
GitHub Actions runner builds from a fresh clone, so anything not in the repo
does not exist there. `output/` is gitignored — the drafts written there are
intermediates, and the batch file is the real record.

The daily workflow then consumes one queued item per run, but only while
`content.script_source` is `"queue"` in `config.yaml`. While it is `"live"`,
the queue is ignored and scripts are generated by the metered API as before.
